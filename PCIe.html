They must correct a relatively big skew automatically (20 ns difference in arrival time is permitted at 2.5 GT/s), and that frees board designers from the sometimes difficult constraint of creating equal-length traces. Together with Polarity Inversion and Lane Reversal, this greatly simplifies the board designer’s task of creating a reliable high-speed Link.

The Link Training and Status State Machine (LTSSM) is a logic block that sits in the MAC layer of the PCIe stack. It configures the PHY and establishes the PCIe link by negotiating link width, speed, and equalization settings with the link partner. This is done primarily by exchanging Ordered Sets, easy-to-identify fixed-length packets of link configuration information transmitted on all lanes in parallel. The LTSSM must complete successfully before any real data can be exchanged over the PCIe link.

Although somewhat complex, the LTSSM is a normal logic state machine. The controller executes a specific set of actions based on the current state and its role as either a downstream-facing port (host/root complex) or upstream-facing port (device/endpoint). These actions might include:

  • Detecting the presence of receiver termination on its link partner.
  • Transmitting Ordered Sets with specific link configuration information.
  • Receiving Ordered Sets from its link partner.
  • Comparing the information in received Ordered Sets to transmitted Ordered Sets.
  • Counting Ordered Sets transmitted and/or received that meet specific requirements.
  • Tracking how much time has elapsed in the state (for timeouts).
  • Reading or writing bits in PCIe Configuration Space registers, for software interaction.

Each state also has conditions that trigger transitions to other states. All this is typically implemented in gate-level logic (HDL), not software, although there may be software hooks that can trigger state transitions manually. The top-level LTSSM diagram looks like this:

The entry point after a reset is the Detect state and the normal progression is through Detect, Polling, and Configuration, to the golden state of L0, the Link Up state where application data can be exchanged. This happens first at Gen1 speed (2.5GT/s). If both link partners support a higher speed, they can enter the Recovery state, change speeds, then return to L0 at the higher speed.

Each of these top-level states has a number of substates that define actions and conditions for transitioning between substates or moving to the next top-level state. The following sections detail the substates in the normal path from Detect to L0, including a speed change through Recovery. Not covered are side paths such as low-power states (L0s, L1, L2), since just the main path is complex enough for one post.

Advanced Error Reporting (AER)

This optional error reporting mechanism includes a new and dedicated set of configuration registers that give error handling software more information to work with in diagnosing and recovering from problems. The AER registers are mapped into the extended configuration space and provide much more information about the nature of any errors. See "Advanced Error Reporting (AER)" on page 685 for a detailed description of these registers.

Errors fall into two general categories based on whether hardware is able to fix the problem or not, Correctable and Uncorrectable. The Uncorrectable category is further subdivided based on whether software can fix the problem, Non-fatal and Fatal.

Based on these classes, error handling software can be partitioned into separate handlers to perform the actions required. Such actions might range from simply monitoring the frequency of Correctable errors to resetting the entire system in the event of a Fatal error. Regardless of the type of error, software may arrange for the system to be notified of all errors to allow tracking and logging them.

Correctable Errors

Correctable errors are, by definition, automatically corrected in hardware. They may impact performance by adding latency and consuming bandwidth, but if all goes well, recovery is automatic and fast because it doesn’t depend on software intervention, and no information is lost in the process.

Uncorrectable Errors

Errors that can't be automatically corrected in hardware are called Uncorrectable, and these are either Non-fatal or Fatal in severity.

Non-fatal Uncorrectable Errors

Non-fatal errors indicate that information has been lost but the cause was likely something other than the integrity of a Link or Device. A packet failed somewhere, but the Link continues to function correctly and other packets are unaffected. Since the Link is still working, recovery of the lost information may be possible, but will depend on implementation-specific software to handle it. An example of this error type would be a Completion timeout, in which a Request was sent but no Completion was returned within the allowed time. Somewhere there was an issue, but it could be something as simple as a random bit error within a Switch that caused the Completion to be routed incorrectly. An attempt at recovery for this case could be as simple as re-issuing the Request.

Fatal Uncorrectable Errors

Fatal errors indicate that a Link or Device has had an operational failure, causing data loss that is unlikely to be recovered. For these cases, resetting at least the failed Link or Device will probably be the first step in any recovery process because it's clearly not operational for some reason. The spec also invites implementation-specific approaches, in which software may attempt to limit the effects of the failure, but it doesn't define any particular actions that should be taken. An example of this type of error would be a receiver buffer overflow, in which case information has been lost because flow control tracking counters have gotten out of sync with each other. Before diving into error handling as it relates to the layers, it will help to first discuss the concept of CRC (Cyclic Redundancy Check) because it's an integral part of PCIe error checking. A CRC code is calculated by the transmitter based on the contents of the packet and adds it to the packet for transmission. The CRC name is derived from the fact that this check code (calculated from the packet to check for errors) is redundant (adds no information to the packet), and is derived from cyclic codes. Although a CRC doesn't supply enough informafion to do automatic error correction the way ECC (Error Correcting Code) can, it does provide robust error detection. CRCs are also commonly used in serial transports because they're good at detecting a string of incorrect bits.

The second is the optional ECRC (End-to-end CRC) that's generated in the Transaction Layer of the sender and checked in the Transaction Layer of the ultimate target of the packet. This is intended to detect errors that might otherwise be silent, such as when a TLP passes through an intermediate agent like a Switch, as shown in Figure 15-3 on page 654. In this illustration, the packet arrived safely on the downstream port of the Switch but while it was being stored or processed within the Switch a bit error occurred. The LCRC only protects TLPs while on the Link. Once the Data Link Layer of the Ingress Port checks the LCRC, it removes it from the packet because a new LCRC will be calculated (which will include the new Sequence Number) at the Egress Port. This means that the packet is unprotected while inside the Switch. This is the purpose of having an ECRC. It is calculated at the originating device and is not removed or recalculated by intermediate devices. So if the target device is checking the ECRC and sees a mismatch, then there must have been an error somewhere along the way even though no LCRC error was seen. Note that using the ECRC requires the presence of the optional Advanced Error Reporting registers, since they contain the bits to enable this functionality.

Chapter 6Retimers

6.1 PCIe Extension Devices

6.1.1 Purpose

To accommodate longer trace lengths on a printed circuit board (PCB), especially at higher data rates.

  • PCI-SIG aims for trace lengths up to 20 inches.
  • At 8.0 GT/s, this is possible with careful layout.
  • At 16.0 GT/s, the practical length drops to 10-12 inches.
  • An active component like a Retimer is needed approximately every 10 inches to extend the length.

6.1.2 Types of Extension Devices (Repeaters)

  • Re-driver: A non-protocol aware, software-transparent device. Its behavior is NOT covered by the PCIe specification.
  • Retimer: A Physical Layer protocol-aware, software-transparent device. Its behavior IS covered by the PCIe specification.

6.2.2 Rules

1. Core Architecture and Operating Rules

  • Maximum Retimer Count: A PCIe link is permitted to have at most two retimers between an Upstream Port and a Downstream Port. The specification explicitly states that platform designers must ensure this two-retimer limit is honored across all PCIe links, including those involving different form factors and active cables. Some form-factor specifications may impose additional rules.
  • Basic Retimer Architecture: Each retimer consists of two pseudo ports, which are dynamically oriented as either upstream or downstream.
  • Operating Modes:
    • Forwarding Mode: When active, both pseudo ports of a retimer must operate at the same data rate.
    • Execution Mode: This mode is used for specific functions, including loopback, Polling.Compliance and during Phase 2 / Phase 3 of link equalization.

2. Reset and Electrical Behavior

  • Fundamental Reset: While Fundamental Reset is asserted, all retimer transmitters and receivers must adhere to the PHY requirements referenced in the specification.
  • Post-Reset Impedance Detection: After reset is de-asserted, the retimer has a defined time limit to determine receiver impedance:
    • Up to 100 ms for most cases.
    • Up to 20 ms if the retimer only supports 5.0 GT/s or less.
  • Impedance and Electrical Idle Rules:
    • A retimer must back-propagate a low impedance state within 1.0 ms after the receiver on its opposite side meets the ZRX-DC requirement.
    • The retimer must keep its transmitter in Electrical Idle on a lane-by-lane basis until ZRX-DC is detected on that lane.
    • A retimer is permitted to change its data rate while in Electrical Idle, and this is the recommended behavior to reduce link exit latency.
    • A retimer is required to infer Electrical Idle based on criteria defined elsewhere in the specification.

3. Equalization and Ordered Set Modifications

  • Equalization Field Modification: The retimer is permitted to modify certain fields within Equalization (EQ) ordered sets:
    • It can overwrite the Transmitter Preset field in EQ TS1 Ordered Sets in both upstream and downstream directions.
    • It can overwrite the 8.0 GT/s Transmitter Preset field in EQ TS2 Ordered Sets in the downstream direction only.
  • Ordered Set Handling Rules:
    • Phase 0 EQ: During Phase 0 of equalization at higher data rates, a retimer is allowed to forward or convert TS2 / EQ TS2 Ordered Sets in an implementation-specific manner.
    • Control SKP Ordered Set: The retimer must modify symbols 4*N+1, 4*N+2, and 4*N+3 of the Control SKP Ordered Set when it is moving in the upstream direction.
    • Error Handling: If an 8b/10b decode error or a disparity error is detected while forwarding, the retimer must replace the erroneous symbol with symbol D21.3 with incorrect disparity.

4. Loopback, Hot Reset, and Compliance Rules

  • Follower Loopback: The retimer must enter Follower Loopback Execution mode when the conditions defined for TS1/Loopback_Request are met. The hot reset and loopback rules are designed to ensure interoperability when one or two retimers are present on the link.
  • Compliance Mode:
    • Specific rules apply for Compliance Receive and Enter Compliance states.
    • This includes checking retimer compliance bits upon exiting a Hot Reset, adjusting the data rate according to the Retimer Target Link Speed, and forwarding compliance patterns only after achieving lock.

5. ECN for Optical Aware Retimer

  • An Engineering Change Notice (ECN) for Optical Aware Retimers adds or updates some rules, including:
    • Clarifying that retimer rules apply to the pseudo ports connected to the electrical link segments only.
    • Providing additional details on Ordered Set handling and compliance.

6.2.3 Operating Modes

  • The Retimer operates in two basic modes, Forwarding mode or Execution mode.
  • When switching between these modes the switch must occur on an Ordered Set boundary for all Lanes of the Transmitter at the same time.
  • When using 128b/130b or 1b/1b the Transmitter must maintain the correct scrambling seed and LFSR value when switching between modes.
  • When switching between Forwarding and Execution modes, the Retimer must ensure that at least 16 TS0/TS1 Ordered Sets and at most 64 TS0/TS1 Ordered Sets are transmitted between the last EIEOS transmitted in the previous mode and the first EIEOS transmitted in the new mode.
  • When switching to and from the Execution Link Equalization mode the Retimer must ensure a Transmitter does not send two SKP Ordered Sets in a row, and that the maximum allowed interval is not exceeded between SKP Ordered Sets.
  1. Forwarding Mode:
    • The primary operating mode after the link is reset.
    • Symbols, Electrical Idle, and Electrical Idle Exit are forwarded through the Retimer even if rx loses symbol lock/block alignment.
    • The Retimer must determine what symbols are being forwarded. This involves performing decoding (8b/10b or 128b/130b) and descrambling, followed by re-encoding and re-scrambling the data before transmitting.
    • It performs lane-to-lane deskew just like a standard port.
  1. Execution Mode:
    • The pseudo ports act as actual component ports.
    • This mode is only used in specific cases: Phase 2 and Phase 3 of link equalization at 8.0 GT/s and 16.0 GT/s, Polling.Compliance state, and Slave Loopback (optional).

6.2.4 Technical Operations

  • Latency: This is the time between a symbol bit arriving at the input of one pseudo port and being transmitted from the output of the other pseudo port. The PCIe specification defines maximum Retimer Latency values based on the data rate (e.g., 64 symbol times at 8.0 GT/s). These latency values are only valid when forwarding valid data in the L0 state.
  • Port Orientation: This is determined by the first side to receive two consecutive TS1s with a non-PAD link number. That port is then designated as the Upstream Pseudo Port, which is critical during the equalization process (Phases 2 and 3).

General Functions

  • Equalization: Performs the equalization procedure independently on each Link Segment.
  • Clock Compensation: Actively inserts or removes SKP symbols in SKP ordered sets.
  • Polarity Inversion: Performs polarity inversion on a per-lane basis.
  • Symbol Modification: Modifies fields of certain ordered sets when forwarding them (e.g., Control SKPs, TS1s, TS2s).

6.3.2 How This Works in Gen 5 and Gen 6

The core hardware limitation of supporting a maximum of two retimers on a single physical link remains identical for both Gen 5 and Gen 6. However, the physical and logical layers handle link discovery and equalization differently due to much faster line rates and changes in signal modulation.

PCIe Gen 5 (32.0 GT/s)

  • Backwards Compatible Handshake: The link initialization process always starts at Gen 1 speeds (2.5 GT/s) using the legacy TS1 and TS2 training sequences. The retimers use the exact bit scheme shown above (RtP and 2RtP bits in Symbol 5) to announce their presence to both the Root Port and the Endpoint.
  • Alternate Protocol Support: Gen 5 introduces negotiation for alternate protocols (like Compute Express Link - CXL) directly within modified TS1 and TS2 sequences. Retimers must parse these protocols and seamlessly transition their operating state along with the link partners.
  • Equalization (EQ) Bypass: To decrease latency and bring-up times, Gen 5 introduces a No EQ / EQ Bypass option. If the channel is of high physical quality, the system can bypass intermediate speed equalization steps to immediately transition the link (including the retimers) to the active L0 data transfer state at 32.0 GT/s.

PCIe Gen 6 (64.0 GT/s)

  • PAM4 Signaling and the TS0 Ordered Set: Gen 6 transitions from NRZ (binary 0 and 1) to PAM4 modulation (four voltage levels per unit interval). Because PAM4 is sensitive to noise before the receiver is calibrated, Gen 6 introduces the TS0 Ordered Set.
    • During initial equalization (Phases 0 and 1), the link partners and retimers communicate using TS0.
    • TS0 is physically designed with alternating bits so that it maps to only two voltage levels (essentially mimicking NRZ) to guarantee error-free detection during initial startup before transition to full PAM4.
  • Retimer Equalization Extend Bit: To manage the complex transmitter coefficients (which expand to a 4-tap FIR filter in Gen 6), a new Retimer Equalization Extend bit is introduced in the training sequences.
    • If retimers are present, they set this bit in the TS0/TS1 sets to extend the phase timing so that every link segment has enough time to negotiate and lock its 64.0 GT/s receiver presets.
  • Strict Step-wise Equalization: Unlike Gen 5, there is no provision to bypass equalization in Gen 6. The link must be fully trained and running at Gen 5 speed (32.0 GT/s L0) first, and then transition step-wise to 64.0 GT/s.
